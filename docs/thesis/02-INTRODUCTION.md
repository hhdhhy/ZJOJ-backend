# 第一章 绪论

## 1.1 研究背景与意义

### 1.1.1 研究背景

随着信息技术的快速发展和互联网教育的普及，编程教育已成为高等教育的重要组成部分。传统的编程教学方式存在以下问题：

1. **反馈延迟**：教师需要手动批改学生代码，反馈周期长
2. **资源不均**：优质教学资源分布不均，难以普惠所有学生
3. **个性化不足**：传统教学难以针对每个学生的特点提供个性化指导
4. **实践机会有限**：课堂时间有限，学生缺乏足够的练习机会

在线评测系统（Online Judge, OJ）应运而生，它能夠自动评判程序的正确性，即时给出反馈，大大提高了编程教学的效率。然而，现有的 OJ 系统大多功能单一，缺乏智能化辅导能力，学生在遇到错误时往往得不到有效的帮助。

近年来，人工智能技术的突破为教育领域带来了新的机遇。大语言模型（Large Language Model, LLM）在代码理解和生成方面展现出强大能力，检索增强生成（Retrieval-Augmented Generation, RAG）技术则能够有效结合领域知识库，提供准确、可靠的智能问答服务。将这些技术与传统 OJ 系统结合，可以构建更加智能、高效的编程学习平台。

### 1.1.2 研究意义

本研究的理论意义和实践价值体现在以下几个方面：

**理论意义**：
1. 探索 RAG 技术在编程教育领域的应用模式
2. 研究多语言代码沙箱的安全隔离机制
3. 分析智能问答系统在垂直领域的优化策略

**实践价值**：
1. 提高编程教学效率，减轻教师负担
2. 为学生提供即时、个性化的学习反馈
3. 降低编程学习门槛，促进教育公平
4. 为其他在线教育平台提供技术参考

## 1.2 国内外研究现状

### 1.2.1 在线评测系统发展

国外知名的 OJ 系统包括：
- **UVa Online Judge**：最早的在线评测系统之一，由西班牙瓦伦西亚大学开发
- **Codeforces**：俄罗斯开发的竞技编程平台，拥有活跃的用户社区
- **LeetCode**：面向求职者的算法练习平台，提供丰富的题目资源
- **HackerRank**：企业级技能评估平台，支持多种编程语言

国内代表性的 OJ 系统有：
- **POJ（Peking University Online Judge）**：北京大学开发的经典 OJ 系统
- **HDU Online Judge**：杭州电子科技大学开发，用户量大
- **洛谷**：面向中学生的竞技编程社区，功能丰富
- **牛客网**：集题库、面试、招聘于一体的综合平台

### 1.2.2 AI 在教育中的应用

近年来，AI 技术在教育领域的应用研究取得了显著进展：

1. **智能辅导系统（Intelligent Tutoring Systems, ITS）**
   - Carnegie Learning 的数学辅导系统
   - Duolingo 的语言学习 AI 助手

2. **代码自动生成与修复**
   - GitHub Copilot：基于 GPT 的代码补全工具
   - CodeT5：代码理解与生成的预训练模型

3. **自适应学习系统**
   - Knewton：个性化学习路径推荐
   - ALEKS：基于知识空间的自适应评估

### 1.2.3 现有系统的不足

尽管现有 OJ 系统和 AI 教育应用各有优势，但仍存在以下不足：

1. **功能割裂**：OJ 系统与智能辅导系统独立，数据无法互通
2. **上下文缺失**：通用 AI 助手不了解具体题目和学生代码，回答针对性不强
3. **安全性问题**：部分系统代码执行环境隔离不彻底，存在安全风险
4. **扩展性差**：单体架构难以应对高并发场景，部署复杂

## 1.3 研究内容与目标

### 1.3.1 研究内容

本研究主要包含以下内容：

1. **系统架构设计**
   - 设计前后端分离的微服务架构
   - 实现容器化部署方案
   - 构建可扩展的模块体系

2. **评测引擎开发**
   - 集成 go-judge 沙箱系统
   - 实现多语言编译和运行支持
   - 设计两阶段编译机制提高效率

3. **AI 助手系统**
   - 构建基于 RAG 的智能问答架构
   - 实现本地向量嵌入和云端 LLM 结合
   - 设计知识库管理和更新机制

4. **用户认证与权限管理**
   - 实现 JWT 身份认证
   - 设计基于角色的访问控制（RBAC）
   - 保障 API 接口安全

### 1.3.2 研究目标

本系统旨在实现以下目标：

1. **功能性目标**
   - 支持至少 3 种主流编程语言的评测
   - 实现题目管理、提交记录、排名等核心功能
   - 提供智能化的编程问答服务

2. **性能目标**
   - 单节点支持 50+ 并发评测请求
   - 平均响应时间低于 2 秒
   - AI 问答准确率超过 85%

3. **可用性目标**
   - 提供 RESTful API 接口，便于前端集成
   - 支持 Docker 一键部署
   - 完善的日志和监控机制

4. **安全性目标**
   - 代码执行环境完全隔离
   - 防止恶意代码攻击
   - 保护用户隐私数据

## 1.4 论文组织结构

本文共分为十章，各章内容安排如下：

**第一章 绪论**：介绍研究背景、意义、国内外现状、研究内容和目标。

**第二章 系统架构设计**：阐述系统整体架构、技术选型依据、模块划分和设计原则。

**第三章 技术选型与实现**：详细介绍核心技术栈，包括 Django、go-judge、ChromaDB、DeepSeek 等。

**第四章 数据库设计**：描述数据库概念模型、逻辑模型和物理模型设计。

**第五章 核心模块详细设计**：深入分析用户认证、题目管理、提交记录等核心模块的实现。

**第六章 AI 助手系统设计**：重点介绍 RAG 架构、向量检索、LLM 集成等关键技术。

**第七章 评测系统实现**：详细说明 go-judge 集成、两阶段编译、结果判定的实现细节。

**第八章 系统测试与性能分析**：展示功能测试、性能测试的结果和分析。

**第九章 部署与运维**：介绍 Docker 容器化部署方案、服务器配置和运维策略。

**第十章 总结与展望**：总结研究成果，指出不足之处，展望未来发展方向。
